# 个人 AI 品牌网站改版 - 需求文档

> Spec: personal-ai-brand-redesign
> 创建时间: 2026-07-21T17:16:19+08:00
> 状态: 自动模式已批准

## 需求原文

> 将现有个人网站改版为更简洁、以文字为主的个人品牌网站。品牌内容围绕 AI、大模型和 Agent，突出 AI 系统架构、技术实现、技术判断、管理与交付能力，但不直接使用 CTO 字样。将实施方案和任务卡写入仓库，并按照任务持续推进；同时解决博客和 Works 的静态页面及 SEO 问题。

## 需求概述

本次改版将 Bing' Works 从作品卡片目录升级为文字优先的个人品牌与技术内容网站。网站以“从模型能力到生产系统”为核心主张，通过真实项目、架构文章和交付复盘呈现 AI 系统架构、Agent 工程化和技术领导力，并以静态 HTML、真实 URL 和结构化数据提升可访问性与搜索收录。

## 用户故事

### R-001: 建立清晰的个人 AI 品牌

**作为** 首次访问网站的技术同行、合作方或招聘决策者，**我希望** 在首屏快速理解 Bing 的专业方向和核心能力，**以便** 判断其在 AI 系统架构与技术领导方面的定位。

**验收标准：**

- **AC-001.1**: GIVEN 用户进入首页 WHEN 首屏完成加载 THEN 页面显示姓名 Bing、核心主张“从模型能力到生产系统”以及 AI Agent、大模型应用架构和工程化交付的定位说明。
- **AC-001.2**: GIVEN 用户继续浏览首页 WHEN 到达能力区域 THEN 页面以文字呈现“AI 系统架构、Agent 工程化、技术领导力”三项能力，并用具体说明代替技能进度条或职位头衔。
- **AC-001.3**: GIVEN 页面展示个人定位 WHEN 检查可见文案 THEN 不直接使用“CTO”字样，也不使用夸张、无法验证的能力或结果描述。

### R-002: 提供极简、文字优先的浏览体验

**作为** 内容导向的访问者，**我希望** 页面层级清楚、装饰克制且在不同设备上易读，**以便** 专注理解观点、项目和文章。

**验收标准：**

- **AC-002.1**: GIVEN 用户访问首页 WHEN 页面渲染 THEN 首页以文字、分隔线和留白建立层级，不使用大幅装饰图、渐变背景、嵌套卡片或装饰性动画。
- **AC-002.2**: GIVEN 用户使用 375px、768px 或 1440px 宽度访问 WHEN 浏览主要页面 THEN 页面无横向溢出，正文保持可读行宽，交互目标不小于 44px。
- **AC-002.3**: GIVEN 用户启用深色模式或减少动态效果 WHEN 页面加载 THEN 文本对比度、焦点状态和内容可读性仍满足 WCAG AA 的基本要求。

### R-003: 用项目案例证明架构与交付能力

**作为** 想了解实际能力的访问者，**我希望** 查看完整 Works 档案和重点项目详情，**以便** 理解 Bing 如何处理约束、做技术取舍并推动交付。

**验收标准：**

- **AC-003.1**: GIVEN 网站包含现有 Works 数据 WHEN 打开 `/works/` THEN 可访问全部 25 个项目，并可按分类筛选。
- **AC-003.2**: GIVEN 用户打开任一 `/works/{id}/` WHEN 页面渲染 THEN 初始 HTML 包含项目标题、定位、说明、演示地址和源码地址（如数据存在）。
- **AC-003.3**: GIVEN 用户打开弼马温、IssuePilot 或 AI 资讯详情 WHEN 阅读案例 THEN 页面呈现背景、职责、约束与判断、架构或工程实现、交付与复盘中的可用内容，并关联相关文章。
- **AC-003.4**: GIVEN 项目属于独立产品域名 WHEN 详情页描述该项目 THEN 详情页以案例视角组织内容，不复制产品站的大段目标关键词内容。

### R-004: 将博客升级为可索引的技术内容体系

**作为** 从搜索或站内导航进入的读者，**我希望** 通过真实 URL 直接阅读完整文章并发现相关内容，**以便** 系统理解 Bing 在 AI 与工程领域的观点。

**验收标准：**

- **AC-004.1**: GIVEN 仓库包含 58 篇 Markdown 文章 WHEN 构建网站 THEN 每篇文章生成 `/blog/{slug}/` 静态 HTML，网页源代码包含标题、摘要和正文。
- **AC-004.2**: GIVEN 用户打开 `/blog/` WHEN 浏览文章 THEN 可按主要专题或标签发现文章，并能进入上一篇、下一篇和相关文章。
- **AC-004.3**: GIVEN 文章含代码、表格、引用或图片 WHEN 页面构建 THEN 内容结构正确且图片路径有效；遇到未知 slug 时生成正常 404 而不是空白内容。
- **AC-004.4**: GIVEN 文章归属 AI 原理、Agent 架构、生产工程或技术领导力 WHEN 页面展示元信息 THEN 可看到对应专题，并能返回专题或博客列表。

### R-005: 建立完整的静态 SEO 基础

**作为** 搜索引擎爬虫，**我希望** 获取唯一、语义完整且互相关联的静态页面，**以便** 正确收录首页、项目和博客内容。

**验收标准：**

- **AC-005.1**: GIVEN 任一首页、项目页或文章页 WHEN 检查 HTML head THEN 存在唯一 title、description、canonical、Open Graph 和必要的结构化数据。
- **AC-005.2**: GIVEN 网站完成构建 WHEN 检查输出目录 THEN 存在 `sitemap.xml`、`robots.txt` 和 RSS feed，且站内 URL 使用同一站点根地址配置。
- **AC-005.3**: GIVEN 用户访问旧 `#/blog/{slug}` 链接 WHEN 客户端脚本执行 THEN 自动迁移到对应真实 URL；站内新链接不再使用 hash 路由。
- **AC-005.4**: GIVEN 正式域名尚未确认 WHEN 本地或预览构建 THEN 域名只通过单一配置项管理，不在多个模板中写死互相冲突的 canonical。

### R-006: 保持内容维护和构建流程可控

**作为** 网站维护者，**我希望** 使用清晰的数据源和构建命令管理项目与文章，**以便** 后续新增内容时自动获得页面和 SEO 信息。

**验收标准：**

- **AC-006.1**: GIVEN 维护者新增或修改 Works JSON 或文章 Markdown WHEN 执行构建 THEN 对应列表、详情页、站点地图和 RSS 自动更新。
- **AC-006.2**: GIVEN 内容数据存在缺失字段、重复 slug 或引用文件不存在 WHEN 执行校验 THEN 构建或检查命令给出明确错误而不是静默生成坏页面。
- **AC-006.3**: GIVEN 新开发环境拉取仓库 WHEN 按 README 执行依赖安装和开发命令 THEN 可启动本地预览并完成生产构建。

### R-007: 保留已有内容与外部链接能力

**作为** 现有网站用户，**我希望** 改版后仍能访问原有项目、文章和评论入口，**以便** 不因视觉与架构升级丢失内容。

**验收标准：**

- **AC-007.1**: GIVEN 现有数据包含 25 个项目和 58 篇文章 WHEN 新站构建完成 THEN 数量一致且所有演示、源码链接保留。
- **AC-007.2**: GIVEN 文章评论使用 Giscus WHEN 用户打开文章页 THEN 评论组件仍可加载，并且第三方脚本不会阻塞正文首屏渲染。
- **AC-007.3**: GIVEN 现有缩略图和文章图片存在 WHEN 打开对应页面 THEN 静态资源返回成功且拥有明确尺寸或稳定占位，避免明显布局跳动。

## 非功能需求

- **性能**: 静态优先，首页不依赖客户端 JavaScript 才能显示核心内容；非首屏图片延迟加载。
- **可访问性**: 语义化标题结构、可见键盘焦点、跳至正文链接、颜色对比度达到 WCAG AA 基本要求。
- **可维护性**: 使用单一内容来源，不在生成页面中手工复制文章正文或 Works 数据。
- **兼容性**: 支持当前主流 Chrome、Edge、Safari 和 Firefox；移动端不依赖 hover。

## 范围外事项

- 不增加后台管理系统、数据库、登录或在线内容编辑器。
- 不重写 58 篇文章的正文，不虚构项目指标、团队人数或商业结果。
- 不为每个独立项目子域名同步实施 SEO 改版。
- 本阶段不引入复杂动画、3D、营销插画或大幅个人摄影 Hero。

## 约束与假设

- 网站继续采用静态托管，允许增加 Node.js 构建步骤。
- 采用 Astro 生成静态页面，保留现有 JSON 与 Markdown 作为内容来源，降低一次性迁移风险。
- 正式站点域名由单一环境变量配置；在用户确认前使用明确的部署默认值并在文档中标注。
- 现有项目缩略图继续作为 Works 页面辅助视觉，不作为首页主视觉。
